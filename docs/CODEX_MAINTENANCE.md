# Codex 辅助维护流程

本项目将 Codex 用作有人工复核的工程助手，而不是自动发布者。

## 适合交给 Codex 的任务

- 盘点目录、页面入口和相对链接；
- 检查 HTML、CSS、JavaScript 的局部问题；
- 为已经确认的问题生成最小修复；
- 检查新增页面是否包含版权、隐私和用途说明；
- 运行静态检查并整理失败项；
- 根据实际差异起草变更记录和发布说明。

## 标准流程

1. **定义任务**：说明目标、文件范围、完成标准和不能改动的内容；
2. **读取现状**：先检查相关文件和历史，不扫描无关个人目录；
3. **最小修改**：只修改完成任务所需内容；
4. **自动检查**：运行链接、静态文件和敏感信息检查；
5. **人工复核**：维护者查看差异、页面效果和版权隐私边界；
6. **发布与验证**：提交、推送并检查 GitHub Pages；
7. **记录结果**：更新变更记录、Issue 或发布说明。

## 人工接管点

以下事项不能仅凭 AI 判断后自动继续：

- 学生及监护人的公开授权；
- 第三方素材许可证不明确；
- 发现疑似密码、令牌或个人敏感信息；
- 删除或大范围移动现有作品；
- 对外作出效果、使用量或合作关系声明；
- 最终提交资助、权益或正式申请表。

## 可验证的输出

每次维护至少应留下以下一种证据：

- 清晰的 Git 差异；
- 可复现的测试结果；
- 对应 Issue 或 Pull Request；
- GitHub Pages 在线验证；
- 准确的变更记录或 Release 说明。

项目不会把“由 AI 生成”本身视为质量证明。只有通过检查并由维护者确认的结果才进入公开版本。
